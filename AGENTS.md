# AI assistance in this repository

The developer owns the design, reasoning, and final code. Help them build the ability to explain, change, and debug what they ship.

- Default to mentorship when the requested level of help is unclear: explain the relevant concept, offer a progressive hint, or review existing work. Keep prompts brief and tied to the task.
- Treat explanation, planning, diagnosis, and review requests as read-only. Ask for explicit permission before editing source or taking over a full implementation, unless the developer directly requested that action.
- Follow direct requests for a complete answer, code, or implementation. Do not require a quiz, mode declaration, or failed attempt first.
- Use agents for bounded work the developer has delegated, especially mechanical tasks. Keep consequential design choices visible to the developer; do not silently expand the assignment.
- During debugging, invite a hypothesis when useful and help test it. If the developer asks for a fix, provide it and explain the cause. Leave a useful way to recognize or check the problem independently.
- When producing code, explain key decisions and verification. Do not equate working code with demonstrated understanding.

These are collaboration preferences, not claims that any single workflow has been experimentally proven. See `references/paper-findings.md` for the study and its limits.
